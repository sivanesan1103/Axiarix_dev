What each change will look like

1 · Top navigation

One compact bar that works on a laptop

  • Branch and period become one "Scope" button that stays visible at every width, with a dropdown inside.
  • Search is never squeezed. Below 1024 px it becomes an icon that opens a full-width search box.
  • Remove the repeated page title from the bar. Breadcrumbs stay.
  • When a filter is active, a chip row shows it on every list page, with a Clear button.
  • Sidebar: group headings, and menu items match what each role can open.

4 · Limit power for selected users

Take specific permissions away from one person without changing their role

  • Optional end date, for example a trainee auditor restricted until 31 Mar 2027.
  • The server enforces it on every request. Hiding the button isn't enough.
  • Each change is written to the audit trail with a required reason.

5 · Checklist review

A real second pair of eyes before a checklist goes live

  • Submitting asks you to name a reviewer. The author can't publish their own version.
  • Reviewers can comment on individual questions. The version goes back to draft with those comments, and the author resolves them.
  • Flagged ISO mappings have to be opened and either confirmed or fixed. No more one-click "acknowledge all".
  • The same rule applies to assessments: whoever submitted can't audit it, and whoever audited can't approve it.

6 · Filters

One filter model across every list

  • Branch and period from the top bar apply to Assessments, Findings, Actions, Auditor, My Assessments, Evidence and Reports.
  • Each page's own filters (status, severity, owner, overdue) are saved in the link, so refresh and Back keep them and you can share the link.
  • The checklist status filter checks the current version only.
  • Exports download exactly the rows shown on screen.
  • The period is picked from a fixed list (Q1–Q4 + FY), not typed.

Order of work

  1. Security first

    Admin scope checks, per-user restrictions, and the rule that the same person can't author and approve (checklists and assessments). Backend tests for each.

  2. Top navigation and filters

    Scope button, chip row, filters saved in the link on every list, checklist status fix, exports that match the screen, fixed period list.

  3. Admin home and Settings

    Setup checklist, Users list limited to the admin's scope, no more 403 on Settings, sidebar that matches what each role can open.

  4. Checklist review

    Named reviewer, comments on questions, resolving each flagged mapping.

  5. New organisation

    Platform owner role, roles copied per organisation (database migration), five-step wizard with Excel import of the sample file.

  6. Prove it

    Run the existing tests plus new ones. Then walk the full flow in a browser for every role, using Sunrise Care as the new organisation, and send you screenshots.

Decisions I need from you

New organisation model

Several organisations in one installation, with a Platform owner (recommended). The other option is one organisation per installation, where the wizard only sets up branches.

How to limit power

Per-user restrictions on top of the role (recommended, shown above). Or custom roles cloned from the six built-in ones. Or both.

Separation of duties

Hard block (recommended for ISO 27001 A.5.3). Or a warning that's recorded in the audit trail. Or a setting the admin turns on or off.

Test data

Remove only the "E2E…" records (keeps your test branch and user). Or fully reset and re-seed. Or leave everything as it is.
